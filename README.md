# Perpix Admin Panel

```sh
pnpm install
cp .env.example .env
pnpm scripts:generate-api
pnpm dev
```

The overview at `/overview` opens after login; other URLs redirect there.
Anonymous visitors return to `/login`. The overview checks the admin identity
and shows period-filtered counts, daily payment activity, AI request statuses
and recent payments from the generated API client. Login uses the same
phone/password, cookie, CSRF and in-memory access-token session flow as
`perpix-app`. Successful login redirects to the overview.
No registration or password-reset UI is included.

The shared admin sidebar links to `/overview` and `/sms-test`, with a
collapsible menu on mobile. The protected SMS test page posts to
`/api/admin/v1/auth/sms-tests`, normalizes Iranian phone numbers, and displays
queue acceptance separately from delivery. Sending has no automatic mutation
retries; rate limits respect `Retry-After` before enabling another send.

## API workflow

Set `VITE_PERPIX_API_URL` to the backend URL. `OPENAPI_URL` optionally overrides
the admin schema URL, and `PUBLIC_OPENAPI_URL` overrides the public schema URL
used to include authentication contracts. Generation first loads the backend
schemas, then tries the sibling `perpix-core-api` Python environment, then an
existing cached schema containing the login contract (with a warning).

`pnpm scripts:generate-api` filters admin/auth paths, resolves referenced schemas,
and generates immutable types and enum maps in `src/services/api/api.ts`.
Do not edit this file manually.

The typed `apiClient` uses `openapi-fetch` with the existing authorized fetch
wrapper: credentials, bearer tokens, coordinated refresh and one retry on 401.
Use services for imperative calls and `useReactQueryApi` inside feature hooks
for server state, for example:

```ts
import { useReactQueryApi } from "@/hooks";

export function useAdminIdentity() {
  const api = useReactQueryApi();
  return api.useQuery("get", "/api/admin/v1/auth/me");
}
```

Components consume feature hooks. The login hook follows the reference app:
TanStack mutation → auth HTTP service → runtime response validation → session
manager. Its request body comes from the generated OpenAPI contract.
Tokens remain in memory; refresh uses the backend cookie and CSRF endpoint.
The backend must allow credentials and expose `X-CSRF-TOKEN` through CORS.
