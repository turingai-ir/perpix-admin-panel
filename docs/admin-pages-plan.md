# برنامهٔ توسعهٔ صفحات پنل مدیریت

این برنامه بر اساس قرارداد OpenAPI فعلی در `scripts/generate-api/_output/openapi.json` تنظیم شده است.
قبل از اجرای هر مرحله، قرارداد API همان بخش دوباره بررسی شود.

## وضعیت فعلی

- ورود با شماره همراه و رمز عبور و مدیریت نشست
- بررسی دسترسی ادمین
- صفحهٔ نمای کلی در `/overview`
- سایدبار مشترک با پشتیبانی موبایل
- صفحهٔ تست پیامک در `/sms-test`
- تولید تایپ‌های API و مصرف آن‌ها با OpenAPI Fetch و TanStack Query

## ترتیب اجرا

### مرحلهٔ ۱: کاربران

صفحات:

- لیست کاربران
- جزئیات کاربر

قابلیت‌ها:

- جست‌وجو، فیلتر و صفحه‌بندی سمت سرور
- مشاهدهٔ مشخصات و وضعیت کاربر
- مشاهدهٔ نشست‌های کاربر
- قطع یک نشست یا تمام نشست‌های کاربر
- مسدودسازی و رفع مسدودسازی
- حذف دائمی کاربر با تأیید صریح و بررسی محدودیت‌های قرارداد API

APIهای مرتبط: `/api/admin/v1/users`، `/api/admin/v1/users/{resource_uuid}` و مسیرهای نشست و مسدودسازی زیر `/api/admin/v1/auth/users/{user_uuid}`.

### مرحلهٔ ۲: مالی

صفحات:

- لیست و جزئیات پرداخت‌ها
- لیست و جزئیات کیف پول‌ها
- تراکنش‌های کیف پول
- نرخ ارز

قابلیت‌ها:

- فیلتر پرداخت‌ها بر اساس وضعیت، مبلغ، کاربر و تاریخ مطابق قرارداد API
- مشاهدهٔ سوابق تراکنش‌ها و تراکنش‌های هر کیف پول
- شارژ کیف پول با تأیید صریح مبلغ و گیرنده
- نمایش و بروزرسانی نرخ ارز
- گزارش روزانه و وضعیت پرداخت‌ها؛ گزارش موجودی، منابع و جهت تراکنش‌ها

APIهای مرتبط: مسیرهای `payments`، `payment/reports`، `wallets`، `wallet-transactions`، `wallet/reports` و `currency-exchange-rate` زیر `/api/admin/v1`.

### مرحلهٔ ۳: اشتراک‌ها

صفحات:

- لیست و جزئیات اشتراک کاربران
- لیست، ایجاد و ویرایش پلن‌ها
- سوابق عملیات اشتراک

قابلیت‌ها:

- فعال و غیرفعال کردن اشتراک کاربر
- ساخت و ویرایش پلن مطابق فیلدهای مجاز API
- مشاهدهٔ سوابق عملیات
- گزارش پلن‌ها و انقضای اشتراک‌ها

APIهای مرتبط: مسیرهای `subscriptions` و `subscription` زیر `/api/admin/v1`.

### مرحلهٔ ۴: هوش مصنوعی و فایل‌ها

صفحات:

- لیست و جزئیات وظایف هوش مصنوعی و پیام‌های هر وظیفه
- لیست و جزئیات درخواست‌های Gateway
- لیست، ایجاد و ویرایش مدل‌ها
- لیست، ایجاد و ویرایش ارائه‌دهندگان
- لیست و جزئیات فایل‌ها

قابلیت‌ها:

- بررسی نتیجهٔ پیام وظیفهٔ کاربر
- درخواست بروزرسانی وضعیت Gateway
- اتصال ارائه‌دهنده به مدل و ویرایش تنظیمات اتصال
- گزارش روزانه و نوع وظایف؛ گزارش درخواست‌ها بر اساس مدل، ارائه‌دهنده و وضعیت
- پیش‌نمایش فایل با URL صادرشده از API
- ویرایش اطلاعات فایل، حذف تکی و حذف گروهی با تأیید صریح
- گزارش فایل‌ها بر اساس نوع محتوا و روز

APIهای مرتبط: مسیرهای `ai-task`، `ai-gateway`، `ai-registry` و `file-manager` زیر `/api/admin/v1`.

### مرحلهٔ ۵: امنیت و تکمیل گزارش‌ها

صفحات:

- نشست‌ها
- توکن‌های API
- رویدادهای امنیتی
- تکمیل صفحهٔ نمای کلی

قابلیت‌ها:

- مشاهده و لغو نشست‌ها و توکن‌ها با توجه به مجوزهای ادمین
- مشاهدهٔ رویدادهای امنیتی
- گزارش نشست‌ها و توکن‌ها
- افزودن خلاصهٔ گزارش‌های مالی، کاربران، فایل‌ها و هوش مصنوعی به overview
- افزودن پیوند از خلاصه‌ها به لیست‌های مربوط با فیلتر مناسب

APIهای مرتبط: مسیرهای `auth/sessions`، `auth/api-tokens`، `auth/audit-events` و `auth/reports` و گزارش‌های هر دامنه زیر `/api/admin/v1`.

## زیرساخت مشترک پیش از مرحلهٔ ۱

- جدول مشترک با صفحه‌بندی سمت سرور
- جست‌وجو، فیلتر و مرتب‌سازی مطابق قابلیت‌های هر endpoint
- نگهداری فیلترها و صفحه‌بندی در URL
- نمایش وضعیت بارگذاری، خطا، دادهٔ خالی و نبود دسترسی
- دیالوگ تأیید عملیات حساس
- قالب مشترک صفحهٔ جزئیات و نمایش خطای فرم

## روش پیاده‌سازی هر مرحله

1. بررسی قرارداد API و تولید مجدد تایپ‌ها در صورت تغییر قرارداد.
2. ساخت لیست و جزئیات.
3. افزودن عملیات تغییردهنده و مدیریت خطاهای آن‌ها.
4. بروزرسانی یا invalidation داده‌های مرتبط بعد از عملیات.
5. افزودن گزارش‌های مرتبط و پیوندهای بین صفحات.
6. بررسی موبایل، دسترسی‌پذیری و کنترل دسترسی.
7. تست جریان اصلی و عبور از build و lint.

کد هر قابلیت در `src/features/<feature>` قرار بگیرد. کامپوننت‌ها از هوک‌های قابلیت استفاده کنند و جزئیات ارتباط با API در سرویس‌ها و هوک‌ها بماند. تایپ‌های تولیدشدهٔ `src/services/api/api.ts` دستی ویرایش نشوند. تمام متن‌های رابط از i18next استفاده کنند.

عملیات حساس مانند شارژ کیف پول، حذف دائمی کاربر و حذف گروهی فایل نیازمند تأیید صریح کاربر در رابط هستند. قابلیت‌ها و فیلدها فقط بر اساس قرارداد موجود ساخته شوند.

## معیار پایان هر مرحله

- اتصال واقعی به API تایپ‌شده
- کنترل نشست و دسترسی و مدیریت پاسخ‌های خطا
- بروزرسانی داده پس از عملیات
- پشتیبانی موبایل و وضعیت‌های بارگذاری، خطا و دادهٔ خالی
- تست جریان اصلی و عملیات حساس مرتبط
- build موفق و lint بدون خطای جدید

## قدم بعدی

آماده‌سازی اجزای مشترک جدول و فیلتر، سپس ساخت لیست کاربران و صفحهٔ جزئیات کاربر. بعد از تکمیل مرحلهٔ کاربران، بخش مالی شروع شود.
